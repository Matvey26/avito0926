# Candidate generation для поиска услуг

Решение задачи на retrieval: для каждого поискового запроса нужно выбрать до
50 объявлений из корпуса. Целевая метрика — Recall@50. Полная постановка и
формат данных описаны в [`TASK.md`](TASK.md).

Лучший результат в тестирующей системе — **0.691468 Recall@50**.

## История посылок

### Первая посылка: TF-IDF со стеммингом

Посылка подготовлена по результатам
[эксперимента 0006](experiments/0006-russian-stemming/README.md). Решение
объединяет word TF-IDF по униграммам и биграммам с русским
Snowball-стеммингом и char TF-IDF по 3–5-граммам. Word-индекс строится по
заголовку, параметрам и описанию объявления, char-индекс — по заголовку. Поиск
ограничивается категорией, а за точное совпадение локации к итоговому score
добавляется мягкий бонус.

[Коммит первой посылки `820f860`](https://github.com/Matvey26/avito0926/commit/820f860309d46b63877cd0a42299b10c13cae8d5)
содержит точный `answer.csv` и соответствующий ему код `solution/`.
[Результат тестирующей системы](https://github.com/Matvey26/avito0926/commit/8a717895b2bb894bcbfcb1ab4a841ee249c2c011)
зафиксирован отдельным коммитом.

Локальная смешанная оценка Recall@50 составила `0.5814`; результат в
тестирующей системе — `0.642955`. После отправки осталось 6 попыток.

### Вторая посылка: fusion трёх retriever-каналов

Итоговое решение собрано по результатам экспериментов 0008–0012. Каждый канал
возвращает top-500 внутри категории:

- word BM25 по униграммам после русской лемматизации, по всем текстовым полям;
- compress-fastText GeoWAC по заголовкам;
- char BM25 по символьным 4-граммам, по всем текстовым полям.

Score каждого канала отдельно min-max нормализуется, отсутствующие кандидаты
получают ноль, после чего три оценки усредняются. К объединённому score
добавляется бонус `0.5` за точное совпадение локации и выбирается top-50.

[Коммит решения `516d572`](https://github.com/Matvey26/avito0926/commit/516d572019cef2745893d307b55d94a2e42f055a)
содержит эксперименты и воспроизводимый pipeline.
[Коммит посылки `79f974b`](https://github.com/Matvey26/avito0926/commit/79f974b50652600ca5b7d0a096c55dbcea0a767f)
фиксирует точный отправленный `answer.csv` и его SHA-256.

Локальная смешанная оценка Recall@50 составила `0.650851`; результат в
тестирующей системе — **`0.691468`**.

## Структура проекта

- [`TASK.md`](TASK.md) — исходная постановка, схема данных, метрика и формат
  посылки.
- [`experiments/`](experiments) — последовательные небольшие эксперименты.
  В каждом каталоге есть код, `README.md` с гипотезой, результатами и ходом
  запуска, а также небольшие отчёты и метрики.
- [`assets/common_code/`](assets/common_code) — общий код построения
  cold/warm-валидации и расчёта метрик. Тяжёлые данные, модели и кеши хранятся
  в `assets/`, но не дублируются в Git.
- [`solution/`](solution) — только актуальный воспроизводимый pipeline второй
  посылки; исследовательского перебора внутри него нет.
- [`KNOWLEDGE.md`](KNOWLEDGE.md) — короткая проектная память: устойчивые выводы
  о данных, результаты экспериментов и отправок.
- [`answer.csv`](answer.csv) — точный файл второй посылки с результатом
  `0.691468`.
- [`AGENTS.md`](AGENTS.md) — правила воспроизводимости, оформления
  экспериментов и переноса выбранного подхода в `solution/`.

## Как читать репозиторий

1. Начать с [`TASK.md`](TASK.md), чтобы понять задачу и Recall@50.
2. Посмотреть EDA и сигналы в экспериментах
   [`0001`](experiments/0001-basic-eda/README.md) и
   [`0002`](experiments/0002-signal-analysis/README.md).
3. Для первой посылки прочитать
   [`0005`](experiments/0005-word-char-tfidf/README.md) и
   [`0006`](experiments/0006-russian-stemming/README.md).
4. Для второй посылки пройти
   [`0008`](experiments/0008-bm25-vs-tfidf/README.md),
   [`0009`](experiments/0009-compress-fasttext/README.md),
   [`0011`](experiments/0011-char-bm25-vs-tfidf/README.md) и
   [`0012`](experiments/0012-three-retriever-fusion/README.md).
5. Затем открыть [`solution/README.md`](solution/README.md) и
   [`solution/run.py`](solution/run.py): там находится финальная сборка без
   экспериментального перебора.

## Работа с AI-агентом

AI-агент использовался как помощник для анализа данных, реализации и запуска
кода. Работа велась исключительно через небольшие контролируемые эксперименты:
одна содержательная гипотеза оформлялась отдельным номером, параметры
перебирались программно, а метрики и конфигурация сохранялись рядом с кодом.

Агент не имел доступа к скрытой разметке benchmark и не загружал посылки в
тестирующую систему. Результаты отправок сообщались пользователем. Подход
переносился в `solution/` только после локальной проверки, после чего pipeline
запускался целиком и отдельно проверял формат `answer.csv`. Существенные
решения и найденные особенности данных фиксировались в `KNOWLEDGE.md`, а
человеческое ревью экспериментов — в комментарии в конце их `README.md`.
