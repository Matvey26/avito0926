## Что делает эксперимент

Сравнивает 50 000 положительных пар с таким же числом случайных отрицательных
объявлений из той же категории. Измеряются покрытие токенов запроса в разных
текстовых полях, совпадение локации, рейтинг, отзывы, доступность контактов и
историческая популярность. Также фиксируется протокол cold/warm-валидации.

## Результаты

Численные результаты сохранены в `feature_comparison.csv` и `report.json`.

- Два главных сигнала для отсечения категорийно-согласованных отрицательных
  примеров — покрытие токенов запроса всем текстом объявления (корреляция с
  меткой 0,829) и точное совпадение локации (0,829).
- Среди отдельных текстовых полей (`заголовок`, `описание`, `параметры`) описание
  даёт среднее покрытие 0,624 у положительных пар против 0,049 у отрицательных,
  заголовок — 0,545 против 0,014, параметры — 0,393 против 0,045. Значит, описание
  полезно, но заголовок даёт наиболее концентрированный дешёвый сигнал.
- Фильтры запроса покрываются параметрами положительного объявления в среднем
  на 0,649 против 0,361 у отрицательных; их стоит добавить в текст запроса и/или
  использовать при переранжировании.
- Историческая частота кликов заметно полезна (корреляция 0,259), а рейтинг,
  отзывы и доступность способов связи сами по себе слабы (не более 0,063).
- После нормализации 916 benchmark-запросов имеют знакомый текст, но только для
  363 из всех 2 452 запросов в benchmark-корпусе есть хотя бы одно объявление из
  истории с тем же текстом. История полезна как добавка, но не как основной
  retrieval.
- Все 34 train-строки с `search_category=0` ведут к объявлениям категории 114.
  Поэтому нулевую категорию нельзя трактовать как буквальный фильтр; для неё
  нужен fallback на основной корпус услуг категории 114.

Для следующих экспериментов фиксируются два режима: cold-валидация полностью
скрывает нормализованный текст запроса из истории, warm-валидация скрывает одну
полную сигнатуру, оставляя другие сигнатуры того же текста. Итоговая
ориентировочная оценка смешивает их в пропорции 63/37, близкой к benchmark.

## Ход эксперимента

Положительные строки выбираются с фиксированным `random_state=20260918`.
Отрицательное объявление равновероятно берётся из уникальных объявлений той же
категории; это не позволяет тривиальному совпадению категории завысить оценку
остальных сигналов.

Запуск из корня проекта:

```bash
.venv/bin/python experiments/0002-signal-analysis/analyze.py
```
