## Что делает эксперимент

Измеряет нижнюю границу качества для четырёх простых генераторов: глобальная
популярность, популярность по категории, популярность по категории и локации,
а также точная история того же нормализованного текста запроса. Гипотеза:
локация и история заметно лучше константы, но без лексического поиска Recall@50
останется низким.

## Результаты

Метрики сохранены в `metrics.csv`, описание разбиений — в `report.json`.

- Глобальная и категорийная популярность практически не работают: смешанная
  оценка Recall@50 равна 0,0007.
- Приоритет объявлений той же локации поднимает cold Recall@50 до 0,0305, warm
  до 0,0328 и смешанную оценку до 0,0313. Это полезный fallback, но не
  самостоятельное решение.
- Точная история текста запроса не улучшила результат поверх location fallback
  на этом разбиении. У разных полных сигнатур одного текста релевантные
  объявления почти не совпадают, поэтому историю следует использовать только
  как небольшой дополнительный пул кандидатов.
- В обоих разбиениях медиана числа релевантных объявлений равна одному; по
  2 500 уникальных нормализованных текстов гарантируют отсутствие перекоса от
  многократного повторения частых запросов.

## Ход эксперимента

Для каждого режима выбираются 2 500 текстов детерминированным SHA-1-хешем.
Cold-режим удаляет из истории все строки выбранного текста; warm-режим удаляет
только выбранную полную сигнатуру и сохраняет другие варианты того же текста.
Корпусом служат все уникальные объявления train, как аналог отдельного
benchmark-корпуса. Валидационные строки исключаются из подсчёта популярности.

Запуск из корня проекта:

```bash
.venv/bin/python experiments/0003-trivial-baselines/run.py
```
