# Эксперимент 0010: dense retrieval на rubert-mini-retriever

## Что делает эксперимент

Эксперимент повторяет методологию 0009, но заменяет усреднение
compress-fastText на готовый SentenceTransformer
[`sergeyzh/rubert-mini-retriever`](https://huggingface.co/sergeyzh/rubert-mini-retriever).
Модель кодирует запросы и документы в 312-мерные векторы; используются её
штатные токенизатор и pooling, контекст до 512 токенов и итоговая
L2-нормализация.

Поиск выполняется по точному cosine similarity внутри целевой категории.
Перебираются два коротких состава документа:

- только заголовок;
- заголовок и параметры;

Для первого варианта запрос содержит только `search_query`, для второго
к нему добавляется `search_infm_params_text`. Модель не требует специальных
префиксов запросов или документов. Char TF-IDF, location bonus и fallback не
используются.

Гипотеза: обученный специально для retrieval трансформер лучше равномерного
mean pooling из 0009 представит короткие предметные тексты и сможет
приблизиться к чистому BM25 из 0008. Лучший dense-вариант сравнивается с BM25
на тех же валидационных сплитах.

## Результаты

Лучшим вариантом оказался документ только из заголовка:

| Состав документа | Cold Recall@50 | Warm Recall@50 | Смесь 63/37 |
|---|---:|---:|---:|
| только заголовок | 0,218567 | 0,223164 | **0,220268** |
| заголовок и параметры | 0,165833 | 0,159397 | 0,163452 |

`rubert-mini-retriever` на заголовках улучшил результат mean pooling
compress-fastText из 0009 на `0,009497`, или на 4,5% относительно него.
Однако чистому BM25 из 0008 трансформер уступил `0,105474`, или 32,4%:

| Модель | Лучшая конфигурация | Cold Recall@50 | Warm Recall@50 | Смесь 63/37 |
|---|---|---:|---:|---:|
| BM25 | лемматизация, униграммы, все поля | 0,341073 | 0,299637 | **0,325742** |
| rubert-mini-retriever | только заголовок | 0,218567 | 0,223164 | 0,220268 |

Добавление длинных параметров ухудшило смесь до 0,163452. Значит, даже
retrieval-трансформер чувствителен к дисбалансу между коротким запросом и
длинным структурным текстом объявления; без отдельного взвешивания полей он не
заменяет BM25 как самостоятельный кандидатогенератор.

Полные метрики находятся в `metrics.csv`, прямое сравнение победителей — в
`comparison.csv`, параметры модели и диагностика — в `report.json`.

## Ход эксперимента

Корпус состоит из 344 825 уникальных объявлений `train.parquet`. Используются
общие детерминированные cold/warm-сплиты по 2 500 запросов, Recall@50 и смесь
`0.63 * cold + 0.37 * warm`.

Зависимости и закреплённая ревизия модели подготавливаются командами:

```bash
uv pip install --python .venv/bin/python sentence-transformers==5.1.1
.venv/bin/python experiments/0010-rubert-mini-retriever/download_model.py
```

Модель сохраняется в `assets/models/sergeyzh/rubert-mini-retriever/`.
Используется ревизия
`4ae6298c749e413b958d64a4b349a907c15a3b54`; файл весов проверяется по
SHA-256 `45ca37ef2fa6e081e029ec6dc2b0545f2cfe00881c57f31d65319460a236e762`.
В завершённом прогоне использовались `sentence-transformers==5.1.1`,
`transformers==4.57.6` и `torch==2.14.0`. Основной расчёт после подготовки
модели не обращается к сети:

```bash
.venv/bin/python experiments/0010-rubert-mini-retriever/run.py
```

Крупные NPY-матрицы эмбеддингов и их метаданные сохраняются в
`assets/experiments/0010-rubert-mini-retriever/`, поэтому завершённые составы
не кодируются повторно при перезапуске. Метрики сохраняются в `metrics.csv`,
сравнение с BM25 — в `comparison.csv`, параметры и диагностика — в
`report.json`.
