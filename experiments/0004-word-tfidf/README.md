## Что делает эксперимент

Строит классический sparse word TF-IDF retrieval и программно сравнивает три
состава документа: только заголовок, заголовок с параметрами, все текстовые
поля. Для каждого состава перебирается фиксированная сетка бонусов за точное
совпадение локации. Гипотеза: лексический retrieval даст большой прирост над
эвристиками, а мягкий бонус локации улучшит топ-50 без жёсткой потери 17%
положительных пар из других локаций.

## Результаты

Метрики сохранены в `metrics.csv`, размер индексов и лучшие конфигурации — в
`report.json`.

- Лучший вариант `all_text` с location-бонусом 0,5 достигает cold Recall@50
  0,4561, warm 0,4808 и смешанной оценки 0,4653 — почти в 15 раз выше лучшей
  простой эвристики из эксперимента 0003.
- Без location-бонуса полный текст даёт только 0,2361/0,2490. Мягкое
  переранжирование хорошо использует сильный географический сигнал и при этом
  не отбрасывает релевантные объявления из соседних локаций.
- Заголовок без бонуса даёт 0,1880/0,2076; добавление параметров —
  0,2128/0,2263; добавление описания — 0,2361/0,2490. Каждое поле приносит
  измеримый прирост.
- Полнотекстовый индекс содержит 102,2 млн ненулевых весов против 2,3 млн у
  заголовочного. Это заметная цена, но на benchmark-корпусе из 189 тыс.
  объявлений итоговый индекс будет существенно меньше и остаётся практичным.

## Ход эксперимента

Корпус — 344 825 уникальных объявлений train. Используются униграммы и биграммы,
`min_df=2`, не более 200 000 признаков, sublinear TF и `float32`. Для каждого
запроса сначала выбираются 500 лучших лексических кандидатов нужной категории,
затем перебираются location-бонусы `0, 0.05, 0.1, 0.2, 0.3, 0.5`. Категория
запроса `0` трактуется как основной сервисный корпус `114` по результатам EDA.
Cold/warm-разбиения совпадают с экспериментом 0003.

Запуск из корня проекта:

```bash
.venv/bin/python experiments/0004-word-tfidf/run.py
```
