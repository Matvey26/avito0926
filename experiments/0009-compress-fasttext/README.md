# Эксперимент 0009: dense retrieval на compress-fastText

## Что делает эксперимент

Эксперимент проверяет предобученные русские word embeddings из проекта
[compress-fastText](https://github.com/avidale/compress-fasttext) как
самостоятельный dense retriever. Используется рекомендованная авторами
21-МБ модель `geowac_tokens_sg_300_5_2020-100K-20K-100.bin`, сжатая из
300-мерной модели GeoWAC.

Для каждого текста усредняются исходные fastText-векторы токенов, после чего
документ L2-нормализуется. Поиск выполняется по точному cosine similarity
внутри целевой категории. Единственная перебираемая ось — состав документа:

- только заголовок;
- заголовок и параметры;
- заголовок, параметры и описание.

Для первого варианта запрос содержит только `search_query`, для двух остальных
к нему добавляется `search_infm_params_text`. Нормализация, pooling, модель и
retrieval не меняются. Char TF-IDF, location bonus и fallback не используются.

Гипотеза: dense-сходство сможет находить семантически близкие объявления без
точного совпадения слов, а добавление описания даст лучший состав. Лучший
dense-вариант сравнивается с BM25 из эксперимента 0008 на тех же сплитах.

## Результаты

Лучшим dense-вариантом оказался документ только из заголовка:

| Состав документа | Cold Recall@50 | Warm Recall@50 | Смесь 63/37 |
|---|---:|---:|---:|
| только заголовок | 0,205913 | 0,219042 | **0,210771** |
| все текстовые поля | 0,053693 | 0,051227 | 0,052781 |
| заголовок и параметры | 0,030280 | 0,032780 | 0,031205 |

Сравнение победителей 0009 и 0008:

| Модель | Лучшая конфигурация | Cold Recall@50 | Warm Recall@50 | Смесь 63/37 |
|---|---|---:|---:|---:|
| BM25 | лемматизация, униграммы, все поля | 0,341073 | 0,299637 | **0,325742** |
| compress-fastText mean pooling | только заголовок | 0,205913 | 0,219042 | 0,210771 |

Dense retrieval уступил BM25 на `0,114971`, или примерно на 35,3% относительно
результата BM25. Гипотеза о пользе описания для простого mean pooling не
подтвердилась.

Диагностика показывает сильное разбавление сигнала: средний заголовок содержит
4,1 токена, документ `title_params` — 161,0 токена, `all_text` — 305,4 токена.
Параметры объявлений представляют собой длинный структурный текст, тогда как
параметры запроса добавляют в среднем только около 3,4 токена. При равномерном
усреднении общие и шаблонные слова подавляют короткий предметный запрос.

Практический вывод: простое усреднение compress-fastText нельзя использовать
как самостоятельную замену BM25. Если возвращаться к этим эмбеддингам, нужно
отдельно проверять взвешивание полей и токенов либо использовать dense-оценку
только как небольшой дополнительный сигнал к лексическому retrieval.

Полные метрики находятся в `metrics.csv`, прямое сравнение победителей — в
`comparison.csv`, диагностика и параметры модели — в `report.json`.

## Ход эксперимента

Корпус состоит из 344 825 уникальных объявлений `train.parquet`. Используются
общие детерминированные cold/warm-сплиты по 2 500 запросов, Recall@50 и смесь
`0.63 * cold + 0.37 * warm`.

Зависимости и модель подготавливаются командами:

```bash
uv pip install --python .venv/bin/python compress-fasttext==0.1.5
.venv/bin/python experiments/0009-compress-fasttext/download_model.py
```

Модель сохраняется в `assets/models/compress_fasttext/` и перед запуском
проверяется по SHA-256
`5fdb4135d96fab4ab99a64ee71ffd5263c850e4f3f64aec6632c168e70a6cee9`.
В завершённом прогоне использовались `compress-fasttext==0.1.5` и
`gensim==4.4.0`.
Основной расчёт не обращается к сети:

```bash
.venv/bin/python experiments/0009-compress-fasttext/run.py
```

Результаты сохраняются в `metrics.csv`, сравнение с BM25 — в
`comparison.csv`, параметры и диагностика — в `report.json`.
